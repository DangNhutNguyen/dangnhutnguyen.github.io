# Neural Work: A Second Brain Must Not Replace the First

*Logbook 15 · Late August 2026*

The project is called Neural Work. In its most ambitious version, it is a "second brain" that can work alongside a person: understand goals, arrange tasks, preserve knowledge, and receive some signals from wearable devices to adjust the way it offers support. The user would not have to keep explaining that they are overloaded, losing focus, or in need of rest; the system might recognize part of that state. Read this far, and the idea sounds a little like a science-fiction trailer. So the first thing I need to write is that Neural Work **does not read minds**, does not make decisions in place of a person, and is not yet a complete startup. It is a collection of hypotheses that need to be reduced until they can actually be tested. Projects like Focumia and Dailynox began with the same problem: I have more tasks, documents, plans, and projects than I can hold in working memory. A productivity app can store information. A knowledge base can create links. AI can summarize or suggest the next step. But most systems still wait for users to report their own state with great accuracy. That is quite a strong assumption. When I am tired, I am least likely to update the system. When I am overloaded, looking at a long list adds another layer of cognitive load. When I am focusing well, even an "intelligent" notification can still ruin the session.

I began to wonder: could the system adapt to the person, instead of forcing the person to keep serving data to the system? When brain–computer interfaces are mentioned, people easily think of Neuralink or implanted devices. That is not a realistic starting point for two students. A more feasible direction would be non-invasive signals and indirect indicators: consumer EEG, with all its limits in noise and resolution; heart rate or heart-rate variability; movement, sleep, and interaction time; on-device behavior, such as the pace of task switching or pause duration; very brief, intentional feedback from the user. No single signal says, "This person is understanding the lesson." The same pattern can come from many causes. So the first goal should not be to infer a complex mental state. A smaller question might be: with the user's consent, can combining a few signals detect when a study session is beginning to deteriorate better than a clock alone? That is a question for which an experiment can be designed. "Build a second brain" is not-at least, not yet. If Neural Work has value only when a BCI device works perfectly, the project will almost certainly die before it reaches a user.

I think the first version should be software-first: the user enters goals, documents, and time constraints; the system suggests one next step small enough to take, together with a reason; the user accepts, edits, or rejects it; the system learns from deliberate feedback instead of silently guessing everything; biological data, if present, remains an additional signal and can be turned off completely. Before anything else, a useful second brain must be good at preserving context. It needs to know where a project stopped, what an earlier decision was based on, and which documents are relevant. This is a difficult problem, but it does not have to wait for the hardware of the future. If the version without EEG helps no one, adding EEG will only make the failure look more technological. The idea opens several AI questions that seem concrete enough for me to investigate. General models often ignore differences between users. Can a personal baseline be learned from very little data, then adapted over time? Users will not label their own state every minute. How can occasional self-reports be combined with continuous, noisy signals? Recognizing a state is not enough. A suggestion delivered at the wrong time may do more harm than no suggestion at all. The effect of the intervention has to be evaluated, not only the classifier's accuracy.

Biological and behavioral data is deeply sensitive. If inference can run on-device, the system has less need to send raw data elsewhere. This also connects directly to my interest in resource-efficient AI. Users need to know what data is collected, what the model has inferred, and why the system is recommending an action. "There is an off button" is not enough if the user does not understand what is on. Each question above could become a prototype or a small paper. They would still have value even if Neural Work never became the product first imagined. A tool that knows when users are tired, distracted, or more vulnerable to influence could help them. It could also become a machine that optimizes productivity so aggressively that it treats people as resources. So I want to set a few principles before writing the features: users own their data and can truly delete it; collect as little as possible and prefer local processing; every inference about a person's state comes with uncertainty; do not make medical diagnoses from devices that were not designed to diagnose; do not use vulnerable states to increase engagement; every important recommendation needs a reason and the right to refuse; measure success by whether the system helps users reach goals they chose themselves, not by how many hours it keeps them inside the app. If these principles make the product harder to build, that is not overhead. It is part of the problem.

A startup application cannot consist of a vision alone. "AI + BCI + second brain" contains too many nouns and no users yet. For Neural Work to become a convincing project, our team needs a small wedge: a specific group of people, a recurring problem painful enough to matter, and an improvement that can be measured. For example, help self-learning students return to the right context after an interruption, then test whether an adaptive plan raises the completion rate of study sessions without increasing stress. Before YC comes the user interview. Before hardware comes the prototype. Before the pitch deck comes data showing that the problem is real. If no one needs the small version, there is no reason to believe they will need the version with more sensors attached. I like the idea of a second brain because it promises to free memory from the things a machine can hold more reliably: deadlines, document links, project states, and the history behind decisions. But there are things the first brain must not hand away: choosing what is worth pursuing, doubting a recommendation, changing a goal, and taking responsibility for a decision. Neural Work is worth building only if it makes those abilities stronger. A second brain that is very good at its job but makes the first brain think less is not an upgrade. It is only a form of dependence with a beautiful interface.
