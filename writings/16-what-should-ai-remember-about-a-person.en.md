# What Should an AI Remember About a Person?

*Logbook 16 · September 2026*

Every time I move to a new application, I introduce myself again. The goal I am pursuing. Where a project stopped. The kind of feedback I prefer. An old decision and the reason behind it. These details are scattered across notes, calendars, messages, and my own memory. That is why the promise of an AI that “understands you” is so attractive. But the more I think about Neural Work and a Personal OS with long-term memory, the more I see that the difficult question is not how to make AI remember more. The difficult question is this: what is it allowed to treat as truth about a person? I might say, “I want to study economics these days.” That could be a long-term goal, a three-month experiment, or simply an idea I had one evening. If an AI stores the sentence as a permanent attribute-“Nhựt wants to switch to economics”-it has done more than remember. It has interpreted. And interpretations can be wrong. People change their minds. They speak within a context. They try on a role and later leave it behind. A good memory system must distinguish between: what the user has just said; what has been confirmed repeatedly; what was only true during a particular period; what has since been replaced; what two sources disagree about; and what the system is not certain enough to store as a “fact.” Without those layers, personalization can become an old label following the user around.

When an AI says, “I remember that you prefer this approach,” the user should be able to ask: where did that memory come from? Something I confirmed directly in a conversation is different from an inference based on my click history. A private note is different from a sentence written by someone else in an email. A website or an external PDF certainly should not be able to write into my personal profile that I trust a particular person, want a particular outcome, or belong to a particular group. To me, every important memory needs at least four things: **Source:** where the information came from; **Time:** when it was said or when it was true; **Confidence:** whether the user confirmed it or the AI inferred it; **Revision history:** what later replaced or contradicted it. This may sound like implementation detail. It is actually the condition that allows a user to challenge the system. Without a visible source, I cannot correct a false memory. Without time, AI may use last year’s goal to make today’s decision. Without preserved contradictions, the system chooses one version of me without asking. Many products say that users can delete their data. In an AI system, however, removing one line from the interface does not necessarily remove its influence.

The information may remain in a search index, a summary, an embedding, a cache, or a model that learned from it. “Forget” therefore needs to be an operation that can be verified, not merely a disappearing animation. I think users need three very clear rights: to see what the AI retains about them; to correct or mark information that is no longer true; to remove both the original data and the representations derived from it within the scope the system promises. An AI that lives with a user for years cannot turn the past into a prison built from personalization. People have the right to become someone else. The direction I want to explore with Neural Work and the Personal Intelligence Research Platform (PIRP) is local-first: personal data has a canonical copy controlled by the user, can be exported or moved to another tool, and remains useful without a cloud connection. That does not mean everything must run perfectly on a small laptop. Some tasks may need a more capable model or synchronization across devices. But the architecture should begin with the question of who owns the personal state, not which provider finds it most convenient to store it. If changing models means losing an entire digital memory, that memory never truly belonged to the user. If a company can lock my history inside a format I cannot take with me, the second brain has become rented memory.

A system with long-term memory creates a new attack surface. If an email, website, or document can convince an AI to write an instruction into memory, an attacker does not need to seize control immediately. They only need to plant an assumption that the system will reuse days later. External content should therefore be stored only as an observation with a source. It should not directly rewrite a user’s goals, trusted people, action policies, or confirmed preferences. A good memory system does not ask only, “Is this information useful?” It also asks, “Who has the authority to make the system believe it?” That is why I see memory as a security boundary, not a convenience feature placed beside chat history. The more an assistant knows, the better it may become at making context-aware suggestions. It also becomes more capable of manipulation, confident misinterpretation, or exposing private parts of a person’s life. The goal should not be to understand everything. The goal should be to understand only enough to support a task the user has chosen, within boundaries the user can see and revoke. If I am writing a paper, the AI can remember the research question, the sources I have read, and the reasons behind a methodological decision. It does not need to construct a complete psychological profile. If I am planning my week, it may use my deadlines and free time. It does not need to decide that I lack discipline.

Sometimes, good personalization means knowing when to stop inferring. I still want to build a system that can live with a user for longer than one chat session-a place that preserves project state, the reasons behind decisions, and the links among goals, documents, schedules, and actions. But if that system works, I do not want its proudest claim to be, “AI knows everything about you.” A better standard is whether: it can show why it believes something; it knows when information may be outdated; it preserves contradictions instead of silently selecting one version; it asks before turning an inference into a memory; and it genuinely forgets when the user asks it to. An AI that understands me is not an AI that always has an answer about me. Sometimes, it is an AI honest enough to say, “I should not store this as truth yet.”
